01The task

Every image (512 × 512 px) was watermarked by one of three public, post-hoc watermarking methods: PixelSeal (Meta, 256-bit message), TrustMark (Adobe, 100 bits) or StegaStamp (100 bits). Post-hoc means the watermark is added to an existing image by an encoder network, and a decoder network reads the message back from the whole image.

After watermarking, the images were edited. For each test image we must say which parts still carry the watermark: a binary mask with 1 = watermarked and 0 = clean. The organisers give us, for every test image, the method and the exact message that was embedded. That turns out to be the most useful piece of information we have.

The hard part, in the organisers' words: these methods were trained to decode one message from a whole image, not to tell you where the watermark is. The question of the task is whether we can make them localise anyway.

Outpainting

A rectangle in a bigger picture

The whole watermarked image is shrunk and extended into a larger generated canvas. The mask is a clean rectangle.

Object removal / alteration

A hole in the watermark

An object is edited out of a watermarked image. The mask is “everything except the edited object”.

Object addition

Another hole

Something clean is pasted on top of a watermarked image, covering the watermark there.

Transplantation

A watermarked object

An object cut from a watermarked image is pasted into a clean image. Only the object is watermarked.

02How the score works

The answer is scored on a 128 × 128 grid: one cell covers 4 × 4 pixels, and a true cell counts as watermarked if at least half of its 16 pixels are. Per image the score is the mean IoU over the two classes:

IoUc = |Pc ∩ Gc| / |Pc ∪ Gc|,   mIoU = (IoU0 + IoU1) / 2,   score = mean over images

The consequence that drives every decision: the smaller class of each image is worth half its score. If an image is 95 % watermarked with a 5 % hole, predicting “all watermarked” gets IoU1 = 0.95 but IoU0 = 0, so only 0.475. Finding the hole is the other half. Try it:

0.000
both say watermarkedboth say cleandisagree

Rule of thumb. Any constant mask scores at most 0.5 per image. On our train set, all-0 scores 0.252 and all-1 scores 0.248, because about half the images are mostly watermarked and half mostly clean.

05The cluster and Slurm

JURECA has login nodes (where we type, edit, and run small checks; they have internet) and compute nodes (A100 GPUs, no internet), which we can only use through the Slurm queue. The organisers reserved 30 nodes (reservation cispahack) for all teams. Three facts shape how we work:

  1. A job always gets a whole node of 4 GPUs, even if it asks for one (the partition allocates nodes exclusively). So every job should use all 4 GPUs.
  2. One node per person at a time (organiser rule; offenders lose GPU access). We never queue a second job while one is waiting or running.
  3. Waiting is the expensive part. Jobs waited 2–3 hours today, while most of our runs take minutes. So we test ideas cheaply first, and once we hold a node we keep it busy instead of giving it back.

07Step 1: hand-made signals

Why. Before training anything, measure what simple maps already know. Each map is scored the same way: cell-level AUC over all train cells, and 5-fold CV mIoU of a threshold chosen on the training folds.

The signals. Residual energy: what is left after a 3 × 3 median filter, per cell. Agreement map: the decoders end with “average over positions, then a linear layer”, so we can apply that linear layer at every position before averaging and compare the per-position bit guesses with the known message. Window decoding: decode crops of 64, 128 and 256 px and score how well each matches the message.

The agreement is exact for PixelSeal and TrustMark: averaging the per-position logits reproduces the real logits (error 2·10⁻⁶ and 9·10⁻⁸). StegaStamp ends with dense layers on the flattened map, so it has no exact per-position version.

PixelSeal97.1 %agreement map, standardised per image0.470
TrustMark97.1 %window decoding0.465

What we learned. Decoding the whole image and comparing with the known message separates full from partial images almost perfectly (AUC 0.998–0.999). That gate alone is worth +0.20. But inside an image the maps barely help: standardised per image, the agreement map drops to AUC about 0.54, and small windows decode nothing (AUC about 0.5).

Step 1b tried three more maps (PixelSeal's own detection channel, TrustMark's watermark remover, a matched filter that re-embeds the known message). None beat step 1. The matched filter works on images we watermark ourselves, but finds nothing on the real ones, so the real watermarks no longer exist as exact pixel patterns.

08Decoding crops: rectangles can be found exactly

Why. The task text says outpainting shrinks the whole watermarked image into a bigger canvas. Every decoder resizes its input to a fixed square, so decoding exactly that rectangle should reproduce the geometry used at embedding time and give back the message.

The oracle test. Decode the ground-truth bounding box of each partial train image (agreement: 1 = perfect, 0 = random).

So the refinement becomes a post-processing step: it needs a rough guess (from the network) and it only keeps a rectangle when the crop actually decodes the message. Objects and holes never decode, so they are left to the network.

09Step 2: the network

Why a network. Holes and transplanted objects make up about three quarters of the images, and no hand-made map finds them. We need a model that looks at the pixels and learns what each watermark looks like locally.

Why Watermark Anything. Meta's Watermark Anything (ICLR 2025) was trained to say, pixel by pixel, where its own watermark is, including after splicing and inpainting. Its MIT-licensed extractor is a SAM ViT-B encoder (93 M parameters) with a pixel decoder. We keep the pretrained body, which already knows how to look for invisible patterns, and replace its last layer.

Each detection channel starts from WAM's own detection weights, so on day one the network already “sees” watermark-like texture. Running at 512 px needs the position tables of the transformer stretched, which the constructor does.

10Synthetic training data

Why. 510 real masks are few for a 93 M-parameter model. But we have the three embedders, so we can make unlimited examples with exact labels by repeating the organisers' recipe on clean COCO photos (5,000 images with object outlines).

Afterwards half of the images get a mild whole-image change (JPEG, resize or noise), because the real pipeline clearly re-processed the images: the matched-filter test showed exact pixel patterns are gone. Checked with the decoders before scaling up: full synthetic images decode at 0.75–1.00 agreement, the exact box of a synthetic outpainting decodes, and transplanted objects do not, just like the real data.

11Training and evaluation

Loss. Binary cross-entropy on the detection map, plus soft Dice on both classes (it mirrors the metric, which also weighs both classes equally), plus a bit loss: on watermarked cells, the bit maps must predict the known message.

  1. Pretrain on synthetic data only, three variants side by side on the 4 GPUs: input 256 px, input 512 px, and 256 px with a 3× higher learning rate. Twice per epoch, each variant is scored on all 510 real train images, which it has never seen.
  2. Pick the best variant automatically by that real-train score.
  3. Fine-tune with 5-fold CV: for each fold, train on the other 4 folds of real images mixed 1:1 with synthetic ones, and predict the held-out fold. Together the 5 folds give an honest prediction for every train image.
  4. Train once on all 510 and predict the 1,020 test images.
  5. Post-process (tuned in CV): threshold per method, the full/partial gate, removing tiny specks, and rectangle refinement where the crop decodes.

12Step 2 result: not good enough

The job started at 19:17. The dry run caught one bug (a learning-rate schedule with zero warm-up for very short runs), which was fixed on the running node without queueing again. Then everything ran: 18,000 synthetic images in 5 minutes, three pretraining variants, the automatic pick (256 px), and 5-fold fine-tuning.

Why it failed. Inside each real image the network's map was close to random. It learned the synthetic watermarks, but the real ones look different at pixel level: the same matched-filter measure gives 0.03 on freshly embedded watermarks and 0.002–0.024 on the real images, while both decode perfectly. An SDXL autoencoder round trip does not explain it (it breaks PixelSeal: agreement 0.55); a FLUX autoencoder round trip comes closer (decoding stays at 1.00, pattern drops to 0.02).

Two more ideas were tested and dropped with numbers: rectangle boxes proposed by the network found a decodable box for only 3–12 % of partial images, and decoder attribution maps (occlusion, gradients) only helped PixelSeal full images (AUC 0.71).

13Step 3: decoder-feature probes (the breakthrough)

Idea. The network failed because Watermark Anything's features were never trained on our three watermarks. But each decoder's own early layers were: they exist to pick up exactly that watermark's texture. So instead of a big network, we take the decoder's intermediate feature maps, which are still spatial (64 × 64 cells), and train a tiny convolutional head on them to say “watermarked or not” per cell.

Features. PixelSeal: ConvNeXt stages 0–1 (plus stage 2 in the “deep” version). TrustMark: ResNet layer1–2 (plus layer3). StegaStamp: conv layers 2, 4 and 5, exposed by adding them as outputs of a copy of the ONNX graph. The image is resized exactly as the decoder resizes it, so the features see the watermark at the scale it was trained on.

Scoring and submitting use one shared protocol: evalmaps.py (5-fold CV: gate threshold and one map threshold per regime fit on the training folds) and make_sub.py (the same, refit on all 510 images, applied to the test maps).

14The node worker

Because waiting for a node costs hours, step 2 is one 16-hour job. It runs the pipeline, then stays on the node: each GPU keeps taking the next command dropped into slurm/queue/. New experiments start within seconds, without queueing again. The job runs from a frozen copy of its shell scripts (bash reads scripts while running them, so editing them mid-job could break it), while Python files are read fresh by every new command.

Sharing the node with teammates. The organisers allow one job per team, so teammates use our node instead of submitting. A command dropped into the queue runs on our node (jrc0423) on one free GPU; we keep at most two of our own commands running so at least two GPUs stay free.

17Glossary

mIoUMean over the two classes of intersection over union, per image, then averaged over images.
Regime / gateFull (whole image watermarked, with holes) vs. partial (a watermarked part in a clean image). The gate decides it from the whole-image decode.
AgreementHow well decoded bits match the known message: mean of (2m−1)·tanh(logit). 1 = perfect, 0 = random.
AUCChance that a random watermarked cell gets a higher signal than a random clean cell. 0.5 = useless.
5-fold CVSplit train into 5 parts (balanced by method and regime); fit on 4, score on the 5th; repeat. Every score we report comes from the held-out part.
Oracle testAn experiment that cheats on purpose (uses the true mask) to learn whether an idea could work at all, before building it.
Slurm / reservationThe cluster's job queue; cispahack is the set of 30 nodes reserved for the hackathon until 22 Nov, 14:00.
WAMWatermark Anything (Sander et al., ICLR 2025): a model trained to localise its own watermark pixel by pixel. We reuse its extractor.
